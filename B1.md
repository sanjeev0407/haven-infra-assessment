# B1 – The Glacier cost gotcha

## Actual cost impact
Glacier classes have a minimum storage duration: 90 days for Glacier Flexible
Retrieval and Glacier Instant Retrieval, 180 days for Deep Archive. Deleting
before that does not stop the charge. AWS bills the remaining days as an
early-deletion fee.

Day 30: object transitions to Glacier. Day 40: deleted after 10 days in Glacier.
The 90-day minimum applies, so we pay for the other 80 days up front:

    early-delete charge ≈ size_GB × price_per_GB_month × (80 / 30)

For Flexible Retrieval at about $0.0036/GB-month (verify current pricing for
your region), that is about $0.0096 per GB. For Deep Archive the remaining 170 days
apply. Also paid:
- the lifecycle transition request fee (per 1,000 objects, so it adds up with millions of small photos)
- about 40 KB of per-object metadata overhead in Glacier plus S3 Standard, which is
  painful for small photos
- if versioning is on, a delete only adds a delete marker. Noncurrent versions
  keep billing until a noncurrent-version expiration rule removes them.

The cost is "quiet" because the delete succeeds, nothing errors, and the fee
shows up as an EarlyDelete usage type in the bill. It is a recurring leak: every
seller deletion in days 31-120 triggers it, and a budget based on "30 days
Standard then Glacier" never models it.

## Redesign
1. **Archive later than the deletion window.** Transition to Glacier at day 90+
   (or after the longest realistic deletion-request window), so a deletion costs
   nothing extra.
2. **Or avoid minimum durations.** Use S3 Intelligent-Tiering from day 0. It has no
   early-delete fees and no retrieval fees, and it auto-tiers cold data.
3. **Deletion-aware lifecycle.** Tag objects by listing status (`status=sold`).
   Scope the rule with a tag filter and `object_size_greater_than` so tiny objects
   are not archived at a loss.
4. **Handle versions.** `noncurrent_version_expiration`, expired-delete-marker
   cleanup, and `abort_incomplete_multipart_upload`.
5. **Budget it explicitly.**
   expected_cost = archived_GB × P(delete within 90 days of archiving) × remaining_days_fee.
   Add an AWS Budget or Cost Explorer alert on the EarlyDelete usage types,
   and a cost-allocation tag (`landlord_account_id`) so it rolls up to the billing unit.

Sketch:

    rule {
      id     = "sold-photos"
      status = "Enabled"
      filter { tag { key = "status" value = "sold" } }
      transition { days = 90, storage_class = "GLACIER_IR" }
      noncurrent_version_expiration { noncurrent_days = 30 }
      abort_incomplete_multipart_upload { days_after_initiation = 7 }
    }
